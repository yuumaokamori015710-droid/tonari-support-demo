# となり — フロントエンド・プロトタイプ

「危ない日に、1人で帰らせない」

危険な帰宅・移動を避け、友人・家族、タクシー、警備会社、学校・職場、警察への相談につなぐための操作デモです。アプリ単体で襲撃を防ぐことはできません。実際の支援サービスとしては利用できません。

## 起動方法

### インストール不要

`docs/index.html` を最新のChrome・Edge等で開いてください。HTML/CSS/JavaScriptのみで動作し、ビルド、APIキー、外部ライブラリは不要です。

### ローカルサーバー（推奨）

Node.jsがある環境で、このフォルダーをターミナルで開きます。

```powershell
node server.cjs
```

ブラウザーで http://127.0.0.1:4187 を開きます。終了は `Ctrl+C`。同じポートが使用中の場合は `server.cjs` の末尾のポート番号を変更してください。サーバーはループバックのみにバインドし、4つの公開ファイル以外は配信しません。

`npm start` でも起動できます。`npm install` は不要です。

## データの扱い

- データはタブのJavaScriptメモリー内のみ。再読み込み・タブを閉じると消えます。localStorage、Cookie、IndexedDB、外部API、解析タグは使いません。
- 架空の情報だけで試してください。この版に記録の永続保管・バックアップ機能はありません。
- テキストレポートを明示的に保存した場合、そのファイルは端末に残ります。印刷・PDF保存もブラウザーの機能を使用します。
- 「画面を隠す」は表示をメモ画面に替えるだけです。ブラウザー履歴、入力データ、OSのサムネイルやスクリーンショットを消す機能ではありません。

## 画面構成

|画面 / URLハッシュ|操作・役割|
|---|---|
|ホーム `#home`|大きな「いま危ない」「帰宅サポートを使う」「記録する」。状況整理とレポートへの入口|
|緊急 `#emergency`|110番の発信手順表示、緊急連絡先・現在地の共有プレビュー、無音のブザー表示、有人施設等への待機案内|
|帰宅サポート `#support`|状況 → 支援方法 → 共有範囲・確認の3ステップ|
|依頼状況 `#status`|9種類のステータス、進行履歴、共有内容、別の支援への再依頼|
|支援担当 `#staff`|共有を選択した依頼内容、ステータス更新、不成立理由、担当メモ。認証のない役割デモ|
|記録一覧 `#records`|記録の追加・編集・削除（削除確認あり）|
|記録入力 `#record`|日時、場所、種別、内容、証拠メモ、目撃者、相手情報、危険度、行為の回数|
|相談レポート `#report`|警察・弁護士・学校・職場を選択し、全記録の事実整理テキストを生成・保存・印刷|
|状況整理 `#risk`|選択肢によるリスクレベル表示。未選択は判定しない|

電話、位置情報、連絡先へのアクセス、録音・撮影、共有、配車、警備会社への相談を実行するコードはありません。ブザーは表示のみで音・振動もありません。警察庁の案内リンクだけは、利用者が押すと外部サイトを開きます。

## 体験手順

1. 「帰宅サポートを使う」から状況と支援方法を選択する。
2. 共有項目は初期状態ですべてOFF。「現在地」等の必要な項目だけを選び、架空の内容を入力する。
3. デモ依頼を作成し、「支援担当」に切り替える。選ばなかった項目が表示されないことを確認する。
4. ステータスを順番に更新する。別の依頼では「手配不成立」を選び、理由を入力して更新する。
5. 「記録」から架空の被害記録を追加し、編集する。レポート画面で「いつ・どこで・誰が・何を・何回」が反映されることを確認する。
6. レポート内容を確認してテキストを保存する。不要になった記録は一覧で削除する。
7. 緊急画面のボタンはデモ表示だけで、発信や送信を行わないことを確認する。

## 状態遷移

```text
依頼作成済み
  → 支援担当が確認中
  → 手配調整中
  → 手配確定
  → 合流待ち
  → 合流済み
  → 移動中
  → 到着済み（終了）

到着済み以外の各途中状態
  → 手配不成立（理由必須・終了）

手配不成立 → 別の支援を相談 → 新しい依頼を作成
```

状態の飛び越し・逆戻り・終了済み依頼の変更は許可しません。自動で時間経過による状態変更はしません。担当画面の操作でのみ変化し、履歴に時刻を追加します。途中の「手配不成立」は、合流後等では支援継続不能も含む簡易モデルです。本運用ではキャンセル、途中中断、連絡不能等を分離する必要があります。

このプロトタイプでは5つの支援方法すべてに同じフローを適用します。「待機」「学校/職場に共有」に対する専用完了条件は今後の仕様化事項です。

### 共有範囲

依頼ID・支援方法・作成日時・ステータスは依頼処理に必要な基本情報として表示します。現在地・目的地・相談理由・過去の記録・相手情報・緊急連絡先は、選択した項目だけを依頼データにコピーします。「相談理由」を選んだ場合のみ、最初に選択した状況も含めます。

「過去の記録」は依頼作成時点の全記録・全フィールド（相手情報や証拠メモを含む）のコピーです。個別記録・個別フィールドの除外は未実装です。元の記録を後で編集・削除しても、そのコピーは変わりません。この版では依頼後の共有撤回はできません。認証やアクセス制御としての保護ではなく、画面の共有仕様を試すものです。

### リスク表示

|入力|表示|
|---|---|
|未選択|判定なし|
|不安・違和感|レベル1：不安・違和感|
|繰り返すつきまとい・待ち伏せ|レベル2：明確なつきまとい|
|脅し・身体への危害・侵入|レベル3：高リスク|

複数に当てはまる場合は高いレベルを表示します。臨床的・統計的に検証された尺度ではありません。低いレベルでも危険がないという意味にはなりません。記録欄の危険度は本人の選択であり、このルールとは別に保持します。

### 相談レポート

入力済みの記録を時系列に整形するローカルテンプレートです。生成AIや法的判断は使用しません。未記入は「未記入・不明」、回数空欄は「不明」とし、記録件数と入力された行為回数を別々に表示します。複数記録に同一行為を記入した場合、回数は重複し得るため、相談前に確認してください。原文の事実性を検証・認定する機能はありません。

## セキュリティ・法務・運用上の注意点

1. **実運用には未対応**：支援者、タクシー、警備会社、学校・職場、警察との契約・接続・受け入れ体制はありません。手配成立や到着の表示もデモです。アプリから実際の110番発信は行いません。
2. **機微情報**：端末を見られる・共用されるケース、アカウント乗っ取り、加害側のアクセスを想定した脅威分析が必要です。メモリー保存も端末の閲覧や開発者ツールからのアクセスを防ぎません。
3. **認証・権限**：本運用には利用者と担当者の認証、最小権限、担当案件単位の認可、多要素認証、監査ログ、なりすまし対策が必要です。
4. **同意とデータ管理**：共有先・目的・期間の明示、同意・撤回、第三者提供、保管期間、削除、暗号化、バックアップ、委託先管理、漏えい対応等を専門家と設計してください。
5. **記録の扱い**：原本・作成時刻・編集履歴・タイムゾーン・証拠の保全方法を別途設計してください。現在の版では編集履歴を残さず、真正性や証拠能力を保証しません。報告は本人の申告であり、違法行為の認定ではありません。
6. **手配と責任分界**：受付時間、対応地域、費用、資格・契約、応答期限、未応答時・不成立時の連絡先、学校等の窓口、未成年者対応、本人確認と合流確認を運用担当・法務と詰める必要があります。
7. **緊急対応**：利用者を依頼の待機列に留めない設計が必要です。緊急連絡への案内、電話が使えない場合や障害時の導線、アクセシビリティ、誤操作を含め当事者支援の専門家と検証してください。
8. **画面上の防御**：入力内容はHTMLエスケープして表示。CSPで外部通信を制限。ローカルサーバーはカメラ・マイク・位置情報をPermissions-Policyで禁止。これらだけで本運用の保護が完成するわけではありません。

警察庁は、緊急の事件・事故は110番、緊急でない相談は#9110または最寄りの警察署を案内しています。[警察庁：ご意見、各種相談・情報提供等](https://www.npa.go.jp/goiken_index.html)（参照：2026-09-27）。関連情報：[警察庁のストーカー相談窓口](https://www.npa.go.jp/hanzaihigai/portal/search/kensaku/st/index.html)。このREADMEは個別事案への法律相談ではありません。

## モバイル版と公開方法（2026-11-07）

[UI Pocket](https://www.ui-pocket.com/mobile) の公開画面例（ソフィBe、マイナアプリ）を参考に、記録への短い入口と、目的別の大きな操作行を採用しました。掲載画像は使用していません。下部ナビ中央は緊急案内、支援担当デモはホーム末尾または依頼状況から開けます。

GitHub Pagesでは main ブランチの /docs を配信します。公開版はHTTPSで開けます。閲覧時にはホスティング先へページ取得の通信が発生しますが、記録や共有フォームの入力値は送信しません。デモのデータは再読み込みで消えます。
